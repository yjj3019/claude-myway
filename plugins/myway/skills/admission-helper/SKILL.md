# admission-helper: 대학별 요강 분석

## 이 스킬이 존재하는 이유

같은 학생부가 대학에 따라 5.8등급이 되기도 하고 7.4등급이 되기도 한다. 차이를 만드는 것은 학생이 아니라 대학의 산출 방식이다. 그런데 그 방식은 모집요강 원문에만 정확히 적혀 있고, 입시 사이트 요약이나 기억에 의존하면 반드시 틀린다.

요강을 직접 열어야만 드러나는 것들의 예:

- 지방 국립대는 정원의 절반 가까이가 지역인재 몫이다. 수도권 고교 출신은 그 자리를 쓸 수 없다. "모집 700명"이 실제로는 0명일 수 있다.
- 전 교과군을 반영하고 학년 가중치가 없는 대학에서는, 특정 교과 조합을 노린 전략이 통째로 무효가 된다.
- 등급점수표가 특정 등급부터 급락하는 대학이 흔하다. 평균등급이 같아도 손실 폭이 크게 달라진다.

대학 이름이 나오면 추정하지 말고 요강을 연다.

## 개인정보 취급 원칙

**학생 개인정보를 이 스킬 폴더에 저장하지 않는다.** 실명, 학교명, 주소, 학번, 성적표는 스킬의 일부가 아니다. 스킬은 재사용·공유되는 패키지이므로, 여기에 개인 데이터가 들어가면 그대로 외부로 나간다.

학생 데이터는 매번 런타임에 확보한다. 대화 내용, 사용자가 올린 파일, 프로젝트 파일에서 읽는다. `references/profile-template.md`가 필요한 항목의 목록이며, 채워진 프로필은 사용자의 작업 공간에 두고 스킬 폴더에는 두지 않는다.

분석 결과물에 이름이 들어가는 것은 사용자 본인의 문서이므로 무방하다. 문제는 **재사용 가능한 산출물**에 개인 데이터를 하드코딩하는 것이다.

## 절대 원칙

**추정치를 사실처럼 쓰지 않는다.** 확인한 것과 확인하지 못한 것을 항상 구분해 표기한다. 합격선을 모르면 "미확인"이라고 쓰고 그럴듯한 숫자를 지어내지 않는다. 근거 없는 숫자 하나가 원서 한 장을 버리게 만든다.

출처는 세 등급으로 표기한다.
- `[요강]` 해당 대학 모집요강 원문에서 직접 확인
- `[공식]` 교육부·대교협·법령 등 공적 자료
- `[미확인]` 검증 못 함 — 판단 근거로 쓰지 않음

## 작업 순서

### 1. 학생 프로필을 확보한다

`references/profile-template.md`의 항목이 채워져 있는지 확인한다. 대화나 사용자 파일에서 읽어 온다. 빠진 항목이 있으면 추정하지 말고 사용자에게 묻는다.

**지원 자격 제약을 가장 먼저 확정한다.** 출신 고교의 소재 권역, 읍·면 여부, 기회균형 해당 여부. 이게 정해지지 않으면 모집인원 계산이 전부 틀어진다.

### 2. 요강 원문을 확보한다

검색어는 `"<대학명> <학년도> 수시 모집요강"`. 대학 입학처 도메인(`enter.*`, `iphak.*`, `admission.*`)이나 요강 PDF가 걸리면 페이지를 열고, PDF는 텍스트를 추출해 읽는다.

요강을 못 찾으면 시행계획이라도 확보하되, 시행계획은 요강보다 정보가 성기다는 점을 명시한다. **둘 다 못 구하면 그 대학은 "요강 미확보"로 처리하고 분석하지 않는다.** 반쯤 아는 상태로 판정하는 것이 가장 위험하다.

### 3. 아홉 개 항목을 뽑는다

`references/extraction-checklist.md`에 각 항목을 요강 어디서 찾는지와 흔한 함정이 정리되어 있다. 처음 다루는 대학이면 읽는다.

1. 지원 자격 — 특히 지역인재·지역균형·농어촌 등 자격 제한 전형과 그 모집인원
2. 반영교과 — 교과군, 과목 수, 계열별 차이
3. 학년별 반영비율 — 균등인지 특정 학년 가중인지
4. 반영 기간 — 3학년 1학기까지가 표준
5. 등급점수표 — 등급 간 간격이 균등한지
6. 진로선택과목 반영 방식과 비중
7. 수능최저학력기준 — 모집단위별로 다름
8. 전형요소 배점
9. 실무 정보 — 모집인원, 원서접수 일정, 전형료, 감점 규정

### 4. 학생 성적을 대입한다

`scripts/grade_calc.py`로 환산점수와 실질 반영등급을 계산한다. 사용법은 스크립트 상단 주석에 있다. 환산식은 사칙연산과 `x`만 허용한다.

놓치기 쉬운 것들:

- **등급 간 간격이 균등한지 확인한다.** 특정 등급부터 급락하는 표에서는, 그 구간에 과목이 몰린 학생이 평균등급으로 예상되는 것보다 훨씬 큰 손실을 본다. 스크립트가 이 차이를 "구조적 손실/이득"으로 출력한다.
- **반영교과가 조합을 허용하는지 본다.** 전 교과군 반영이면 최적 조합 전략 자체가 무효다.
- **학년 가중치가 있으면 해당 학년 등급을 따로 대입한다.** 성적이 상승 추세인 학생은 3학년 가중 대학에서, 하락 추세인 학생은 균등 반영 대학에서 유리하다.
- 정확한 계산에는 과목별 이수단위가 필요하다. 단위 정보가 없으면 교과 평균등급으로 근사하고, **근사임을 반드시 표기한다.**

### 5. 분석 카드를 출력한다

대학 하나당 아래 형식을 그대로 쓴다. 형식이 고정되어야 여러 대학을 나란히 비교할 수 있다.

```markdown
## <대학명> · <전형명>

**판정** 지원 가능 / 자격 미달 / 요강 미확보
**실질 반영등급** <값> (기준선 <값> 대비 <±값>)

| 항목 | 내용 | 이 학생에게 |
|---|---|---|
| 지원 자격 | | |
| 반영교과 | | |
| 학년 반영비율 | | |
| 등급점수 구조 | | |
| 진로선택 | | |
| 수능최저 | | |
| 전형요소 | | |
| 모집인원 | | |

**유리한 점**
**불리한 점**
**미확인** — 입시결과 등

**근거** <요강 명칭 및 공지일 / 확인 시점>
```

자격 제한 전형이 있는 대학은 전형별 모집인원을 자격 판정과 함께 별도 표로 만든다. 총 모집인원이 아니라 **자격 있는 전형의 인원만이 유효 모집인원**이다.

### 6. 여러 대학이면 배치표로 묶는다

세 곳 이상을 다뤘으면 마지막에 실질 반영등급 오름차순 표를 붙인다. 컬럼: 대학·전형·실질등급·기준선 대비·수능최저·유효 모집인원·판정.

**합격선을 확인하지 못한 상태에서 안정·소신·상향을 임의로 배정하지 않는다.** 실질 반영등급 순서만 제시하고, 입시결과 확보가 선결 조건임을 밝힌다.

## 자주 나오는 함정

**지역인재를 빼먹는 것.** 지방 국립대의 지역인재는 해당 권역 고교에서 전 교육과정을 이수한 학생만 지원할 수 있다. 수도권 고교 출신에게는 처음부터 닫혀 있다.

**평균등급만 보는 것.** 누적 평균은 흐름을 가린다. 학년별 등급을 나란히 놓고 상승·하락 추세를 확인한다. 학년 가중 반영 대학에서는 강약점 구도가 뒤집힐 수 있다.

**분석 프로그램의 환산값을 대학 방식으로 착각하는 것.** 사설 분석 리포트는 예체능 성취도를 임의 등급으로 환산해 전교과 등급을 만든다. 대학 산출식과 다르므로 지원 판단에 쓰지 않는다.

**수능최저를 통과했다고 가정하는 것.** 모의고사 성적이 없으면 충족 여부를 계산할 수 없다. 기준만 적고 판정은 보류한다. 내신 등급으로 수능 등급을 추정하지 않는다.

**요강이 바뀌는 것.** 모집요강에는 대개 "추후 변경 가능" 문구가 있다. 확인 시점과 공지일을 함께 적어 둔다.

## 참고 파일

- `references/profile-template.md` — 학생 프로필 항목 목록. 채운 결과는 스킬 폴더가 아니라 사용자 작업 공간에 둔다.
- `references/extraction-checklist.md` — 요강에서 항목을 찾는 위치와 함정.
- `scripts/grade_calc.py` — 환산점수 계산기.

## 특정 정보가 필요할 때

학생 개인정보(이름, 학교, 성적표)와 지원 자격 정보는 파일이나 저장소에 미리 적지 않는다. `references/profile-template.md`의 빈 항목을 모아 한 번에 질문하고, 받은 답은 이번 분석과 세션에만 쓴다. 미성년자의 정보이므로 필요한 항목만 최소로 받는다. 주민등록번호 같은 식별번호는 요청하지 않는다.
