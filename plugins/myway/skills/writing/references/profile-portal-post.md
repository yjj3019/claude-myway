# 프로필: portal-post

조직이 운영하는 기술 블로그·포털에 올리는 게시글. Notion 같은 블록 에디터에 그대로 붙여 넣을 수 있는 Markdown을 산출한다.
이 프로필은 특정 조직의 규격을 담지 않는다. 사이트별 값(태그 셋, 저자 문구, 시리즈 규칙)은 사용자가 제공하거나 작업 디렉터리의 `portal-profile.md`에 둔다. 값이 없으면 질문 한 번으로 받는다.

## 1. 먼저 확인 (모호하면 질문, 추측 금지)

| 항목 | 기본값 |
|---|---|
| 글 유형 | 아래 5종 중 선택 |
| 분량 | 본문 2,000~3,500자 |
| 시리즈 | 단편 |
| 태그 셋 | 사용자가 제공한 목록. 없으면 질문 |
| 저자 문구 | 사용자에게 확인 |

글 유형 5종:
1. 트렌드·개념 소개형: 독자의 질문 → 정의 → 구성 요소 → 선택 기준
2. 실전 가이드형: 목표 → 준비 → 단계 → 확인 → 문제 해결. 시리즈로 나누기 쉽다
3. 릴리즈 노트형: 기준 날짜와 버전 → 변경점 → 영향 → 확인 조치
4. 성능 개선·트러블슈팅형: 수치로 시작하는 제목, 측정값 필수, 조건과 한계
5. 거버넌스·전략형: 라이선스·규제·비용 판단 지원

## 2. 작업 순서

1. 원자료(테스트 로그, 릴리즈 노트, 구축 기록)에서 독자가 얻는 결론을 한 문장으로 확정한다.
2. 글 유형을 고르고 4장 골격을 따른다.
3. H3 대주제 4~7개를 먼저 배치하고 살을 붙인다. 헤딩 확정 전에 본문을 쓰지 않는다.
4. 3장 문체 규칙으로 문장 단위 변환.
5. 7장 체크리스트로 자체 검수 후 제출.

## 3. 문체

- 해요체 기본. 설명은 "~합니다", 독자에게 말 거는 문장은 "~해요", "~죠"를 쓴다.
- 한 문장을 한 줄로 쓴다. 3줄 이상 붙은 단락은 쪼갠다.
- 독자 호칭은 "여러분". 2인칭 명령형("하세요")은 체크리스트·권고 항목에서만 쓴다.
- 섹션 전환은 의문문으로 한다. "각각의 특징을 살펴볼까요?"
- 성능·비용·효과의 크기를 주장할 때는 제공된 자료나 실제 측정에 있는 수치와 조건을 쓴다. 근거가 없으면 크기를 주장하지 않는다. 숫자가 없는 공식 정의·기능·지원 조건은 출처를 확인해 유지한다.
- 기능 나열이 아니라 "우리 조직은 무엇을 선택해야 하나"로 수렴시킨다.
- 마케팅 어휘 대신 조건부 서술을 쓴다. "~라면 충분한 ROI가 기대됩니다"

## 4. 골격 (순서 고정)

```
[페이지 아이콘 이모지 1자]
# 제목
[도입 2~4줄: 공감형 질문 또는 현장 문제]
### 이모지 대주제 (4~7개)
#### 소주제 (필요 시)
### 마무리
### 참고 자료
[저자 블록]
```

- 모든 H3에 이모지 1개를 붙인다. 이 프로필은 공통 기준의 "이모지는 요청 시에만"을 적용하지 않는다.
- 콜아웃 패턴을 쓴다: `장점:` `단점:` `요약:` `왜 중요한가요?` `어떻게 사용하나요?` `타겟 유저:`
- 오해가 잦은 지점은 `#### Q. 실무에서 그냥 ~해도 되나요?` → `A. ~` 형태로 끊는다.
- 코드 블록은 언어를 명시하고 바로 위에 한 줄 설명을 단다.
- 마무리는 3줄 요약과 독자 행동 유도 1줄.
- 참고 자료는 링크 3~5개. 재구성한 글이면 출처 문장을 남긴다.
- 저자 블록은 이름과 담당 업무 1~2문장(해요체). 사용자가 제공한 것만 쓴다.

## 5. 제목과 메타

제목은 30자 내외, 아래 4패턴 중 하나.
1. 질문형: `컨테이너 이미지는 어디에 저장되나요?`
2. 수치 후킹형: `최대 65% 공간 절감: <기능명> 알아보기` (수치는 근거가 있을 때만)
3. 콜론 분할형: `실전 <주제> 구축: <범위1>와 <범위2>까지 [<주제> - 2화]`
4. 가치 제안형: `<문제>의 해답, <도구>에서 찾다`

메타 설명(og:description)은 함께 산출한다.
- 2문장, 100~150자
- 앞 문장에 핵심 기술 키워드 3~5개, 뒷 문장은 "~해보세요" 또는 "~만나보세요"로 끝낸다.

## 6. 태그

사용자가 제공한 태그 셋 안에서만 1~4개를 고른다. 새 태그를 만들지 않는다. 태그 셋이 없으면 질문한다.

## 7. 제출 전 체크리스트

- [ ] 3줄 이상 붙은 단락이 없다
- [ ] 모든 H3에 이모지가 있다
- [ ] 수치 근거 없는 성능·효과 주장이 없다
- [ ] 마무리, 참고 자료, 저자 블록이 모두 있다
- [ ] 제목이 4패턴 중 하나다
- [ ] 메타 설명이 키워드를 포함한 2문장이다
- [ ] 태그가 제공된 셋 안에 있다
- [ ] 시리즈물이면 지난 화 링크가 도입부에 있다
- [ ] 고객사명, 내부 시스템명, 미공개 수치가 노출되지 않았다

## 8. 사실 경계

공통 기준(`facts-and-privacy.md`)이 이 프로필보다 앞선다. 체험하지 않은 내용을 체험담으로 쓰지 않는다. 성능 수치는 원자료에 있는 값만 쓰고, 도입의 질문을 실제 고객 발언처럼 꾸미지 않는다.
