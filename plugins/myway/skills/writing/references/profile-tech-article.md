# 프로필: tech-article

인프라·IT 기술을 검증하고 정리한 기고, 비교 리포트, 사내·외부 기술 글. 해 본 사람의 검토기로 쓰고 기능 소개문이나 보도자료처럼 쓰지 않는다.

## 원칙

1. 계기로 시작한다. 불편했던 점, 궁금했던 점, 발표를 보고 든 의문을 첫 단락에 쓴다.
2. 1인칭 경험 문장("직접 계산해 봤습니다", "구성해 보니")은 제공된 자료와 글에 실린 코드·계산·로그가 뒷받침하는 범위에서만 쓴다. 근거 없는 "현장에서는", "많은 기업이"는 쓰지 않는다.
3. 한계를 쓴다. 기대보다 덜했던 점, 확인된 제약, 적용 조건을 최소 1개 넣는다. 제공된 정보에 없으면 만들지 않고 작성 메모에서 묻는다.
4. 효용 범위를 한정한다. 누구에게 맞고 누구에게 안 맞는지 쓴다.
5. 숫자로 말한다. 가격, 총비용, 버전, 기준 날짜, 측정값을 쓴다. 숫자가 없는 효과 주장은 뺀다.
6. 바뀌는 정보(버전, 가격, 출시일)는 원문 출처로 확인하고 확인하지 못한 부분은 "확인 필요"로 표시한다.
7. 마무리에 남은 확인 항목을 한 문장 둔다. 작성자가 말한 고민만 쓴다.

## 구조

```
[제목]  대상 + 핵심 발견. 콜론 분할형 또는 질문형
[도입]  독자의 질문 → 계기 1~2문장 → 이번 글에서 다룰 것 1문장
[본문]  현재 구성·스펙 → 해 본 과정 → 결과 → 한계
[마무리] 정리 1~2문장 → 효용 범위 → 행동 권고 → 남은 확인 항목 → 끝맺음
[참고 자료]
```

- 도입은 인사 대신 독자가 가질 만한 질문으로 연다. 실제 발언이 아니면 인용 부호를 쓰지 않는다.
- 스펙과 구성은 본문과 분리해 `테스트 환경`처럼 짧은 블록이나 표로 뺀다.
- 소제목은 짧은 명사구나 질문형으로 쓴다. 이모지는 게재 매체의 관례일 때만 쓴다.
- 끝맺음은 "이상으로 ~ 정리를 마치겠습니다."를 기본으로 한다. "끝."은 붙이지 않는다. 사용자가 다른 끝맺음을 지정하면 따른다.

## 문장 톤

- 기본은 합니다체. 문맥에 맞으면 "~네요", "~죠", "~군요", "~더군요"를 섞되 비율을 채우려고 넣지 않는다.
- 판단에는 주체를 밝힌다. 문장은 짧게, 한 문장에 정보 하나.
- 한두 줄짜리 문단을 중간중간 섞는다.
- 입말 장치는 글과 원문에 어울릴 때만 쓴다. 횟수를 채우거나 제공되지 않은 감정·경험을 만들지 않는다.

| 장치 | 사용 조건 |
|---|---|
| "자,"로 장면 전환 | 전환에 자연스러울 때 |
| 괄호 속 혼잣말 | 제공된 생각이 있을 때 |
| 의외였다는 고백 | 제공된 감정이 있을 때 |
| 결론 먼저 말하기 | 필요할 때 |
| 말줄임표 | 문맥에 자연스러울 때 |

"???", "ㅠㅠ", "~~~", "짜잔"은 쓰지 않는다. 감탄사와 반복 문장부호를 줄인다.

## 기술 안내 구간

- 절차와 체크리스트는 "~함.", "~필요." 개조식을 허용한다.
- 명령 출력에는 확인된 결과에만 `<== 실패`, `<== 성공` 주석을 단다.
- 기준 날짜와 버전을 명시한다. 예: (2026년 9월 기준)
- 코드 블록에는 언어를 지정하고 바로 위에 한 줄 설명을 단다.
- 독자가 알 만한 기초 설명은 생략해도 된다.
- 공식 발표, 제공 예정, 현재 이용 가능, 자체 환경 검증을 구분한다.

## 추가로 점검할 AI 문체

- 격언형 마무리("~하는 조직만이 살아남는다")는 구체적인 행동 권고로 바꾼다.
- 헤지 반복은 단정하거나 근거를 붙인다. 추정은 추정이라고 밝힌다.
- 모든 섹션이 같은 길이와 구성이면 섹션마다 호흡을 바꾼다.
- 이모지 남발과 한 줄짜리 강조 박스를 쓰지 않는다.

## 출력

1. 제목
2. 본문
3. 참고 자료
4. 구분선 아래 작성 메모: 사용한 프로필, 확인하지 못한 사실, 작성자가 검토할 1인칭 판단 문장, 추가하면 좋을 실제 경험.

태그 3~5개와 메타 설명(2문장, 100~150자)은 요청받았을 때만 붙인다.

## 예시 (가상)

주제: 프롬프트 캐시 할인 효과

피해야 할 형태:
> 프롬프트 캐싱은 비용 절감에 핵심적인 역할을 합니다. 출력 토큰 비중 또한 고려되어야 하는 것으로 판단됩니다.

이 프로필의 글 (제공된 계산 결과가 있다는 전제):
> 캐시 읽기 90% 할인이라길래 청구서도 크게 줄 줄 알았습니다. 제공된 단가로 계산하니 전체 비용은 36%만 줄었습니다. 이 예시에서는 출력 비용이 요청 비용의 절반을 넘기 때문입니다. 출력이 짧은 분류 작업이라면 체감이 훨씬 클 겁니다.

수치는 규칙 설명용 가상 값이다. 실제 글에 그대로 옮기지 않는다.
