# 디자인 시스템 기반 발표자료

사용자가 디자인 시스템 문서와 브랜드 에셋을 따로 주고 그에 맞춘 발표자료(.pptx, 필요 시 Keynote)를 요청할 때 쓴다. 디자인 시스템 문서가 `pptx.md`와 brand-profile보다 항상 앞선다.

## 입력 체크리스트

없는 항목은 한 번에 묶어 요청한다.

| 항목 | 필수 | 설명 |
|---|---|---|
| 디자인 시스템 문서 | 필수 | 레이아웃 규칙, 컴포넌트, 간격 |
| 주요 컬러 | 필수 | HEX 코드 또는 색상명 |
| 폰트 | 필수 | 제목·본문 폰트명 |
| 콘텐츠 | 필수 | 담을 내용 (형식 무관) |
| 출력 형식 | 필수 | .pptx 또는 Keynote |
| 레퍼런스 이미지 | 권장 | 스타일 참고 스크린샷 |
| 청중, 발표 시간, 슬라이드 수, 언어 | 권장 | 톤, 분량, 폰트 선택에 영향 |

## 발표 컨텍스트

| 청중 | 톤 | 용어 | 강조 |
|---|---|---|---|
| 투자자 | 간결, 자신감 | 최소화 | 숫자, 시장 기회, ROI |
| 고객 | 친근, 설득 | 쉬운 언어 | 문제 해결, 혜택 |
| 내부 팀 | 실무, 직접적 | 내부 용어 가능 | 실행 계획, 역할 |
| 임원진 | 전략, 요약 | 핵심만 | 의사결정 포인트 |

- 슬라이드 수: 정보가 없으면 1장 1.5분으로 역산한다. 10분 발표는 6~7장(표지와 마무리 포함).
- 문서 공유용은 슬라이드를 1.5~2배로 늘리고 문장형으로 쓴다. 발표용은 키워드와 이미지 중심.
- 온라인 발표는 본문 24pt 이상과 강한 대비, 오프라인은 20pt 이상.

## 워크플로우

1. **에셋 분석.** 디자인 시스템에서 그리드, 여백, 타이포 스케일, 색 사용 규칙을 읽는다. 레퍼런스 이미지에서 구조 패턴, 반복 모티프, 밀도를 뽑는다.
2. **콘텐츠를 슬라이드로 구조화.** 도입(표지), 문제 정의(1~2장), 핵심 메시지, 데이터·근거, 결론·행동 요청 순서. 슬라이드마다 메시지 하나.
3. **파일 생성.** 내장 `pptx` 스킬로 만든다. 디자인 시스템의 색·폰트를 코드 상수로 선언하고, 레퍼런스의 레이아웃 패턴을 재현하고, 슬라이드마다 레이아웃을 변주한다.
4. **샘플 먼저.** 3장짜리 샘플로 방향을 확인한 뒤 전체를 만든다.
5. **디자인 검증.** 아래 체크리스트로 대조한다.

### Keynote (.key)

Keynote는 바이너리 포맷이라 직접 생성하지 못한다. 사용자에게 어느 쪽을 원하는지 확인한다.
- 옵션 A: 같은 내용을 .pptx로 만들고 "Keynote에서 파일 > 열기로 불러오면 변환됩니다"라고 안내한다. 폰트와 특수 애니메이션은 Keynote에서 다시 확인해야 한다고 알린다.
- 옵션 B: reveal.js나 순수 HTML/CSS 슬라이드로 만들고, 네이티브 Keynote 파일이 필요하면 옵션 A를 쓰라고 안내한다.

## 디자인 검증 체크리스트

- [ ] 컬러가 디자인 시스템 팔레트 안에서만 쓰였다
- [ ] 지정한 폰트만 쓰였다
- [ ] 여백이 디자인 시스템의 그리드와 간격 기준을 충족한다
- [ ] 레퍼런스 이미지의 무드와 일치한다
- [ ] 텍스트가 넘치지 않는다
- [ ] 슬라이드 간 일관성이 유지된다
- [ ] 청중에 맞는 텍스트 밀도다
- [ ] 발표 시간 대비 슬라이드 수가 적절하다
- [ ] 발표 언어에 맞는 폰트다

## 원칙

- 사용자가 준 컬러와 폰트를 바꾸지 않는다.
- 레퍼런스에 없는 디자인 요소를 임의로 추가하지 않는다.
- 크림 배경, 파란 강조색, 제목 하단 구분선 같은 기본 템플릿 스타일을 쓰지 않는다. 디자인 시스템이 그렇게 정의한 경우는 예외다.

## 모호할 때 묻는 것

- 청중과 사전 지식 수준
- 총 발표 시간
- 발표자가 설명하는 형식인지, 자료만 배포되는지
- 온라인인지 오프라인인지
- 발표 언어
- 슬라이드 수 제한, 비율(16:9 기본, 4:3), 애니메이션 필요 여부
