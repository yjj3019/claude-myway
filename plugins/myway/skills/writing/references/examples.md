# 익명화한 편집 예시

아래는 규칙 설명을 위해 만든 가상 예시다. 실제 사용자 글이나 경험을 재현한 자료가 아니다. 입력에 없는 경험·감정·의견을 추가하지 않는 방법을 참고하고 문장 자체를 반복 사용하지 않는다.

## 1. 개인 블로그: 제공된 경험과 감정만 사용

제공된 사실: 사용자는 가상 제품 A를 구매했고 3일 사용했다. 설정 과정은 쉬웠지만 초기 연결은 두 번 실패했다. 사용자는 연결 실패가 아쉬웠다고 말했다. 배터리는 측정하지 않았다.

편집 전:

> 오늘은 혁신적인 제품 A를 알아보겠습니다. 압도적인 배터리 성능과 완벽한 연결 안정성으로 매우 만족스러운 경험을 선사했습니다.

편집 후:

> 제품 A를 사서 3일 정도 써 봤습니다. 설정은 어렵지 않았는데, 처음 연결할 때는 두 번 실패했네요. 이 부분은 조금 아쉬웠습니다. 배터리 사용 시간은 따로 측정하지 않았습니다.

판단: 확인된 구매·사용 기간·실패 횟수와 제공된 감정만 남겼다. "아쉬웠다"는 의견이 입력에 없었다면 추가하지 않는다. 감탄사나 "끝."은 필수가 아니다.

## 2. 기술 안내: 실제 출력과 예시를 구분

제공된 사실: 서비스 상태 확인 명령을 설명해 달라는 요청이다. 실제 서버에서 명령을 실행한 결과는 없다. `sample-service`는 가상 서비스명이다.

편집 전:

> 아래 명령을 실행하면 서비스가 정상 작동하는 것을 확인할 수 있습니다. 모든 환경에서 문제없이 동작합니다.

편집 후:

> 다음 명령으로 서비스 상태를 확인합니다. `sample-service`는 실제 서비스명으로 바꿉니다.

```bash
systemctl status sample-service
```

> 출력의 상태와 최근 로그를 확인합니다. 이 예시에서는 명령을 실행하지 않았으므로 서비스의 정상 동작 여부는 확인하지 않았습니다.

판단: 실행하지 않은 결과를 성공으로 쓰지 않았다. 안내 문서에 필요한 실행 여부 설명은 유지하되, 불필요한 제작 과정 소개는 추가하지 않는다.

## 3. 장애 보고서: 결론부터 쓰되 추정은 보존

제공된 사실: 가상 로그에서 `node-b`의 재시작이 09:51에 확인됐다. `node-a`는 09:50에 통신 단절을 감지했다. 재시작 원인은 확인되지 않았다. 원본 호스트명은 내부 식별정보여서 치환했다.

편집 전:

> 다양한 가능성을 종합적으로 고려한 결과 네트워크 장애로 인해 node-b가 재시작된 것으로 확실히 판단됩니다. 이를 통해 시스템의 중요성을 다시 한번 알 수 있습니다.

편집 후:

> 09:51에 node-b가 재시작된 사실은 확인됩니다. node-a는 그보다 앞선 09:50에 통신 단절을 감지했습니다. 제공된 로그만으로 재시작 원인을 확정하기는 어렵습니다. 재시작 직전의 커널 로그와 전원 이벤트를 추가로 확인해야 합니다.

> 호스트명은 node-a와 node-b로 익명화했습니다.

판단: 결론·근거·미확인 사항·다음 확인 항목 순서로 썼다. 원인을 확정하지 않았고 분석에 필요한 시각은 유지했다. 추가 확인은 문서 목적에 필요한 조치이며 사용자의 개인 계획을 지어낸 것이 아니다.

## 4. AI 기술 글: 제품명과 요청한 요약 유지

요청: ChatGPT와 Claude의 적용 방식을 비교하고 마지막에 3줄 요약을 넣는다. 최신 기능·가격·지원 범위에 관한 사실은 별도 자료로 확인한다.

처리: ChatGPT·Claude라는 제품명을 유지한다. 비교에 필요한 표와 요청한 3줄 요약을 작성한다. 확인되지 않은 기능을 채우지 않는다. "AI 도구명 금지"나 "끝 요약 금지"로 요청을 취소하지 않는다.

판단: 문체 기본값은 주제와 명시적 요구를 바꾸는 근거가 아니다. 이 예시만으로 현재 제품 기능을 설명하지 않는다.

## 5. 행동 주체: 명확하게 쓰되 미확인 주체는 만들지 않기

제공된 사실: 운영팀이 10:00에 설정 X를 변경했다. 10:05에 서비스가 종료됐으며 종료 이유와 주체는 미확인이다.

편집 전:

> 설정 변경이 진행되었으며 이후 서비스 종료가 수행되었습니다.

편집 후:

> 운영팀은 10:00에 설정 X를 변경했습니다. 서비스는 10:05에 종료됐습니다. 종료 이유와 주체는 확인되지 않았습니다.

판단: 확인된 행동 주체만 드러냈다. 사건의 시간 순서를 원인 관계로 바꾸지 않았다.

## 6. 요약: 적용 범위를 남기기

제공된 사실: 가상 시험 환경에서 설정 A는 2회 통과했다. 설정 B는 시험하지 않았고 운영 환경에 설정 A를 적용하지 않았다. 두 문장으로 요약해 달라는 요청이다.

편집 전:

> 시험을 통과했으므로 모든 환경에서 검증을 마쳤습니다.

편집 후:

> 시험 환경에서 설정 A는 2회 통과했고, 설정 B는 시험하지 않았습니다. 운영 환경에는 설정 A를 아직 적용하지 않았습니다.

판단: 요약으로 분량을 줄여도 시험 대상과 운영 미적용 조건은 남겼다. 시험 통과를 운영 검증이나 다른 설정의 결과로 일반화하지 않았다.

## 7. 의미 있는 반복: 상태명 보존

제공된 사실: 가상 문서가 `Affected`와 `Not affected` 상태의 차이를 설명한다.

처리: 두 상태명을 그대로 반복해 사용한다. 반복을 줄이려고 `Affected`를 "문제 있음", `Not affected`를 "해결됨"으로 바꾸지 않는다. "영향 없음"과 "수정됨"은 서로 다른 의미다.

판단: 기술 용어의 반복은 정확한 비교에 필요할 수 있다. 문체 점검 규칙이 정보의 삭제나 상태 변환을 허용하지 않는다.
